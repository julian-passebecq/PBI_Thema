# Theme Forge audit — 2026-09-08

Scope: live https://pbi-thema.netlify.app/ plus repository source review. This is an audit, not a patch or deployment. Attached handoff documents were reference material only.

The production Chromium smoke suite passed earlier in this session. The deeper checks below expose gaps outside that suite. No Power BI Desktop import, Firefox/Safari, or exhaustive accessibility certification was performed.

## Confirmed findings, in suggested fix order

### 1. P1 — Imported custom theme presets disappear from generated JSON

Live reproduction: open JSON → theme.json and paste:

```json
{"name":"Audit preset","visualStyles":{"*":{"AuditPreset":{"background":[{"show":true,"color":{"solid":{"color":"#123456"}}}]}}}}
```

Wait for `applied`, then leave the field. The regenerated theme contains only Emphasis, Quiet, Elevated, Outlined, Panel and `*`; AuditPreset and its definition are gone. The same generator supplies downloaded theme JSON. This silently loses user-supplied formatting.

Source: theme-forge.html:1585 stores imported preset names but not definitions; :1493 generates only built-in presets. The known-presets list at :1476 nevertheless includes imported names, so selection/validation can recognize a preset absent from the generated theme.

Fix: preserve imported definitions and merge supported edits into them, or explicitly identify unsupported content and require an intentional conversion. Add import/export round-trip assertions for custom presets and unsupported properties.

### 2. P2 — Invalid spec structure throws while status remains `valid`

Live reproduction: JSON → dashboard-spec.json, replace the content with:

```json
{"contractVersion":3,"pages":[null]}
```

Observed console exception: `TypeError: Cannot read properties of null (reading 'id')` at :3561, through validateSpec → applySpecText → the live-edit callback. The visible status remained `valid`; the canvas retained its previous state.

Related local validation probes also throw for `{"tables":[{"name":"Sales","columns":{}}]}` and `{"tables":[null]}`. These were isolated Node executions of the actual validateModel function, not live file-upload tests.

Source: :3559, :3568, :4965, :6329. Nested collections and their members are accessed before structural checks; model validation reports a wrong collection type and then still calls forEach on it.

Fix: validate complete nested structure before iteration or state replacement. Catch validation failures at every import boundary and display a specific error while retaining the last valid document. Share the validation path between file import, drag/drop and JSON editors.

### 3. P2 — Leaving the live JSON editor quickly discards edits

Live reproduction: in theme.json, paste `{"name":"Audit fast blur"}` and immediately click the theme-name field. The editor content and theme name revert to the previous theme. The new name never applies.

Source: :4939 schedules application after 320 ms; :4949 clears editingJson and regenerates the editor on blur. The delayed callback then reads the overwritten textarea value.

Fix: commit or validate the pending draft on blur before rendering; capture drafts independently of rendered application state. Preserve invalid drafts for correction rather than replacing them. Add a paste-then-immediate-blur regression check.

### 4. P2 — Opening a panel breaks the mobile layout

Live reproduction: open JSON, then use a 420 × 844 viewport. Observed document scrollWidth was 502 px, and the Close button's right edge was about 502 px. The Close button is outside the initial viewport. Screenshot inspection confirmed clipped panel-header actions and horizontal scrolling.

Source: :479–489 defines the single-line panel header; the mobile rules starting at :630 do not make its actions fit.

Fix: wrap or collapse panel actions and keep Close visible. Extend responsive testing to open panels, long names, full-screen JSON and selected visuals. The current test checks overflow while panels are closed, which explains its earlier pass.

### 5. P2 — Comment removal modifies valid JSON string values

Live reproduction: paste `{"name":"Audit /*literal*/ theme"}` into theme.json. The UI reports `applied`, but the name becomes `Audit  theme`.

Source: :4981 strips block-comment patterns with a regular expression before JSON parsing, including patterns inside quoted strings.

Fix: parse standard JSON directly; if comments are intentionally supported, use a string-aware parser. Assert that literal comment markers in names and URLs survive import unchanged.

## Additional code-level risks

- Undo history uses a 420 ms debounce and suppresses snapshots for 650 ms after undo/redo (:6589–6607). A local isolated probe confirmed that histPush ignores a new edit while restoring is true. Rapid post-undo edits need a browser timing regression test; they may never enter history when their only scheduled snapshot runs during that suppression window. Flush pending edits before undo and avoid suppressing real subsequent user changes.
- Autosave waits 700 ms, silently swallows storage failures, and has no pagehide/visibilitychange flush (:6625). Immediate close/reload can lose the last change; quota failure gives no user-visible indication. Add a saved/unsaved/error indicator and a best-effort lifecycle flush. These failure modes were identified from code, not forced in the live browser.
- Spec file import caps pages/visuals, but JSON application has no equivalent limit (:4960 versus :6361), and drag/drop bypasses the file-picker size check (:7172). Use consistent limits across entry points.

## Test and usability improvements

1. Expand tests around user outcomes: rejected malformed imports, retained drafts, round-trip export content, undo timing and persistence failures. Existing downloads only check filenames, not parsed contents.
2. Validate generated theme files against the declared Microsoft schema and test representative exports in Power BI Desktop. Current checks assert a schema-version string, not schema compliance.
3. Test open panels at each breakpoint, keyboard focus, touch-sized controls and zoom. The initial no-overflow test is insufficient for mobile usability.
4. Clarify import behavior in the interface: what is preserved, converted or unsupported. A generic `applied` result currently hides data loss.
5. Split import/validation, history/persistence and rendering into reviewable modules after regression coverage exists. No framework rewrite is needed to address these bugs.

## Audit hygiene

The manual test spec and theme were restored to the initial sample, the panel was closed, and the temporary viewport override was reset. No production code or deployment settings were changed. Test dependencies installed during the earlier smoke test remain in untracked node_modules; this report is the only new source-controlled artifact proposed by this audit.
